# Fretpad — プロダクト設計 (Vision & Roadmap)

## Context

作者自身がペルソナ。TAB 譜をなぞって弾くことはできるが、音名・コード名・音楽理論が頭に入らず、アドリブができない。多くのギタリストが勧める「**弾く手を止めて、楽譜と音を把握し、書いて、分析する**」という学習法を実践したいが、それを支援するツールが世の中に見当たらない。

既存ツールとの違い:
- Guitar Pro / TuxGuitar → 「再生・採譜」が主目的。書くことで理論を学ぶ設計ではない
- Notion / Obsidian → 文章は書けるが TAB 譜・指板図・コード表を書けない
- Ultimate Guitar 等 → 他人の譜面を消費する場所。自分の学びを蓄積する場所ではない

**Fretpad は「ギター学習の Zettelkasten」**。書く行為そのものが分析であり、蓄積が資産になる。

## プロダクトが目指すもの

> 弾く手を止めて、書いて、分析することで、フレット番号の羅列を「音楽」として理解できるようになるノートアプリ。

### 設計原則

1. **書くことが学習である** — 入力の摩擦は最小に、ただし「音名・度数を意識させる」摩擦は意図的に残す
2. **理論のレンズを重ねられる** — 同じ TAB を「フレット番号」「音名」「キーに対する度数」で見られる。この切り替えこそが内在化の訓練
3. **蓄積が資産になる** — 日々のノートが後から検索・再利用できる
4. **共有できる** — 書いた図は画像として出力でき、SNS やブログ、印刷で使える

### 非ゴール(作らないもの)

- DAW・本格的な再生/録音機能
- 五線譜の本格的な浄書(TAB 中心。五線譜は将来検討)
- 譜面共有プラットフォーム(他人の曲のアーカイブ)
- モバイルでの快適な「編集」(閲覧は対応、編集は PC 前提)

## コア機能(機能の柱)

### 柱 1: 文書ノート + 音楽ブロック

Notion 風のドキュメントに、テキストと音楽ブロックを混在させて書ける。

- **TAB 譜ブロック** — 6弦(将来は弦数可変)の TAB をキーボード中心で高速入力
- **指板図ブロック** — フレットボード上に任意のポジション・スケール・アルペジオをマーキング
- **コード表ブロック** — コードダイアグラム(押さえ方)。コード名から自動生成 + 手動編集
- テキストは Markdown 風(見出し・リスト・強調)。「今日学んだことを言語化する」場所

### 柱 2: 理論レンズ(最大の差別化点)

ブロックに「キー/コードのコンテキスト」を設定すると、表示を切り替えられる:

- TAB の各音に **音名**(C, E♭…)や **度数**(R, ♭3, 5…)をオーバーレイ表示
- 指板図に **スケール構成音** を重ねて、書いたフレーズがスケールのどこを通っているか可視化
- (後続)コード進行に対する **コードトーン/テンション の色分け**

「フレット番号 → 音名 → 度数」の変換を目で繰り返すことが、アドリブに必要な指板の理解につながる。

### 柱 3: 画像出力・共有

- 任意のブロック(または選択範囲)を PNG / SVG でエクスポート
- 描画を最初から SVG ベースにしておくことで、高品質な出力を低コストで実現

### 柱 4(後続): 学習支援

- 簡易再生(Web Audio): 書いた TAB・コードをクリックで鳴らして音を確認
- タグ・キーによる横断検索(「Am ペンタのフレーズ全部」)
- 想起練習(書き溜めた内容からのクイズ)— 将来構想

## ロードマップ

### Phase 0: MVP — 「書ける」
- 文書エディタ(テキスト + ブロック挿入)
- TAB 譜ブロックの入力・編集
- 指板図ブロック、コード表ブロック
- ローカル保存(IndexedDB + ファイルへのエクスポート/インポート)

### Phase 1: 「分析できる」= Fretpad らしさ
- キー/コードコンテキストの設定
- 音名・度数オーバーレイ(TAB・指板図)
- 画像出力(PNG / SVG)

### Phase 2: 「蓄積が活きる」
- ノート一覧・タグ・検索
- 簡易再生(Web Audio)

### Phase 3 以降(構想)
- コードトーン分析、想起クイズ、URL 共有、クラウド同期

## 技術方針(次フェーズで詳細化)

- Web アプリ(SPA)。まずローカルファースト、サーバー・認証なし
- 描画は **SVG**(画像出力・印刷品質と相性が良い)
- TAB 描画は VexFlow / AlphaTab を評価するが、「理論レンズのオーバーレイ」「学習向けの自由な注釈」が要件の中心なので **自前 SVG 描画が有力**(一般的な浄書機能は不要なため)
- データモデルは「ドキュメント = ブロックの列」。音楽ブロックは音高を **弦+フレット** と **実音高** の両方で保持(理論レンズの計算に必須)
