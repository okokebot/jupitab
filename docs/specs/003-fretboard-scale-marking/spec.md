# 指板図のスケール自動マーキングと度数表示 — 要求仕様

## 背景と目的

ペルソナ(vision.md: TAB はなぞれるが音名・度数が頭に入らずアドリブができない)は、「A マイナーペンタのボックスはどこか」「このポジションの音はキーの何度か」を指板上で確かめながら覚えたい。現状の指板図ブロックはマーカーを 1 個ずつクリックして置き、度数ラベルも手入力するしかなく、スケールを知らない人は正しい図を作れない(= 教材にならない)。ルートとスケールを選ぶだけで構成音と度数が自動表示されれば、書く前から指板図が「理論のレンズ」として機能する。

## vision との対応

- **対応する柱**: vision 柱 2「理論レンズ」(指板図にスケール構成音を重ねる、と明記)/ improvement-policy 柱 C-1(ロードマップ順 1 位)
- **非ゴール確認**: DAW 化・浄書・共有プラットフォーム・モバイル編集のいずれにも抵触しない。表示機能のみで再生・編集モデルは変更しない

## スコープ

- 指板図ブロックにルートとスケールを設定する UI(既存の `keyContext` フィールドを使用)
  - UI 用語は「ルート」に統一(「トニック」は使わない)。ルート選択肢は異名同音を併記(例: `C# / D♭`)
  - スケール選択肢は既存 `ScaleType` の 9 種を日本語慣用名で表示し、ペルソナの入口順に並べる(メジャー/マイナーペンタトニック → メジャー → ナチュラルマイナー → ブルース → その他)。フラットに 9 個並べない
  - スケール選択肢に「なし(自動表示オフ)」を含め、これが解除の入口になる
- 設定中は、表示フレット範囲内のスケール構成音を全弦にわたり自動マーキング(**導出表示**: 保存データに書き込まず表示時に計算)
- 自動マーカーのラベル表示切替: **度数 / 音名 / 点のみ**(ラベル非表示)。表示モードはブロックに保存する。UI 表記はスケール選択の「なし(自動表示オフ)」と紛れない語を使う
- 音名表記の ♯/♭ 切替(既存 `KeyContext.preferFlats` を使う)
- ルートには他の構成音と区別できる強調表示。自動マーカーは手動マーカーと一目で区別できるスタイル
- 自動マーカーにホバーで「音名(度数)」のツールチップ(SVG `title` 程度の軽いもの)
- 既存の手動マーカーとの共存(手動が前面・優先)。ラベルが空の手動マーカーがスケール構成音上にあるときは、導出ラベル(現在の表示モード)を表示し続ける
- keyContext 未設定時は「ルートとスケールを選ぶと構成音が自動表示されます」等のヒントをブロック上に表示(空状態の足がかり)
- マーカーエディタの音名表示に度数を併記(スケール設定中のみ)

## 非スコープ

- `ScaleType` へのモード追加(phrygian / lydian / locrian)と異名同音綴りのキーからの自動導出 — improvement-policy 順番 3 の別 spec で扱う(theory.ts の変更はテスト含め独立させたほうが安全)
- TAB ブロックの音名・度数オーバーレイ — 順番 4 の別 spec
- 構成音を `markers` に一括書き込みする「配置」機能 — 導出表示で用が足りるか見てから判断
- コード(コードトーン)基準の度数表示 — キー基準のみ。コード基準は Phase 3 の理論レンズ拡張で
- 自動マーカーの再生(クリックで音を鳴らす)— 再生機能の整備後に検討
- 度数・スケール用語の本格的な凡例/ヘルプ — improvement-policy 柱 A(ヘルプ整備)の spec で扱う。本 spec ではホバーのツールチップまで
- 指板図ブロック専用のキーバインド新設 — 現状マウス操作のブロックであり、まずネイティブコントロールのキーボード到達性(Tab キー)まで

## ユーザーストーリー

1. スケールの形を知らないので、「A マイナーペンタトニック」を選んだら指板上のどこを押さえればいいか見たい。なぜなら教則本の図を書き写すだけでは位置と度数が結びつかないから
2. 自分で書いたポジション(手動マーカー)がスケールのどの音に当たるのか、背景のスケール表示と重ねて確かめたい
3. 度数(R, ♭3…)と音名(A, C…)を切り替えて見たい。なぜなら「フレット → 音名 → 度数」の変換を繰り返すことが内在化の訓練だから(vision 柱 2)

## 受け入れ基準(EARS 形式)

機能:

- **AC-1**: WHEN 指板図ブロックでルート(12 音)とスケール(9 種)を選択する THEN 表示フレット範囲内の全スケール構成音の位置に自動マーカーが表示される
- **AC-2**: WHEN 自動マーカーが表示されている AND ルートまたはスケールを変更する THEN 追加操作なしに表示が更新される(再生成・再描画操作は不要)
- **AC-3**: WHEN ラベル表示を「度数」にする THEN 各自動マーカーに `degreeInKey` に基づく度数(R, ♭3, 5…)が表示される。「音名」では音名(♯/♭ は `preferFlats` に従う)、「点のみ」ではラベルなしの点のみ
- **AC-4**: WHEN スケール設定中 AND 自動マーカーのピッチクラスがルートと一致する THEN 他の構成音と視覚的に区別できるスタイルで描画される
- **AC-5**: WHEN スケール選択を「なし」にする THEN 自動マーカーがすべて消え、手動マーカーだけが残る(既存動作に完全に戻る)

手動マーカーとの共存:

- **AC-6**: WHEN 手動マーカーと自動マーカーが同じ弦・フレットに重なる THEN 手動マーカーが前面に表示され、クリック操作は従来どおり手動マーカーの選択・編集になる
- **AC-7**: WHEN 自動マーカーのみの位置をクリックする THEN 従来どおり手動マーカーが新規作成される。AND WHEN その手動マーカーのラベルが空 THEN その位置の導出ラベル(現在の表示モード)が表示され続ける(調べようとクリックした人から度数情報を奪わない)
- **AC-8**: WHEN 自動マーカーと手動マーカーが同時に表示されている THEN 両者は一目で区別できる(スタイル差。具体値は design / ui-designer で決定)

初見の理解可能性:

- **AC-9**: WHEN keyContext 未設定の指板図ブロックを表示する THEN スケール自動表示の設定への導線(ヒントテキストまたは目立つコントロール)がブロック上で視認できる
- **AC-10**: WHEN スケール選択 UI を開く THEN 各スケールは日本語慣用名で表示される。マーカーエディタには選択位置の音名に加えて度数が併記される(スケール設定中)
- **AC-11**: WHEN ラベル表示(度数/音名/なし)を切り替える THEN ワンアクション(1 クリック)で切り替わり、選択中マーカー等の他の状態を失わない。新設コントロールはすべて Tab キーで到達・操作できる(ネイティブ要素)

エッジケース・永続化:

- **AC-12**(フレット範囲): WHEN `fretStart` が 0 でない(例: 5〜12 フレット表示) THEN 開放弦のマーカーは表示されず、範囲内のフレットのみマーキングされる。`fretStart` = 0 のときは開放弦の構成音もナット左に表示される
- **AC-13**(変則チューニング): WHEN ブロックのチューニングが標準以外 THEN 構成音の位置は `pitchFromTab` によりそのチューニングで正しく計算される
- **AC-14**(永続化): WHEN スケール設定とラベル表示モードを保存して再読込(IndexedDB / JSON エクスポート→インポート)する THEN 両方が復元される。旧データ(該当フィールドなし)も従来どおり開ける
- **AC-15**(undo): WHEN スケール設定・表示モードを変更して undo する THEN 設定変更が 1 操作 = 1 ステップで巻き戻る(不変条件「undo の粒度 = store 更新 1 回」)

## 関連 spec との相互作用

- [002-fretboard-lefty-mirror](../002-fretboard-lefty-mirror/spec.md)(左右反転表示): 反転表示中は自動マーカーも鏡像で表示されるべき。導出マーカーが手動マーカーと同じ座標系で描画される設計なら自然に満たされる — design で確認すること

## 要確認

ユーザーに 2 点質問したが応答がなかったため、以下を仮の判断として進める(変更があれば言ってください):

1. **表示方式は「導出表示」を採用**(一括生成ではなく)。keyContext を設定している間だけ表示時に計算し、`markers` には書き込まない。スケール変更に即追従し、譜面データが古くならない。improvement-policy 柱 C-1 の記述とも整合
2. **ラベルは「度数 / 音名 / なし」の 3 択切替を採用**(度数固定ではなく)。「なし」はラベルを隠して自分で度数を思い出す自己テストとしても機能する(ux-designer も支持)

spec 作成時・レビュー反映時の判断(質問はしていない):

3. **ラベル表示モードはブロックに保存する**(度数⇄音名の往復は高頻度だが、ノートを開き直したとき前回の見え方が復元されるほうが学習ノートとして自然)。省略可能フィールド追加のみで旧データはデフォルト値(度数)にフォールバック — schemaVersion 昇格は design で要否判断
4. **♯/♭ は既存 `preferFlats` の手動トグル**とし、キーからの自動決定は順番 3 の theory.ts 改修 spec に送る。ルート選択肢は併記(`C# / D♭`)でどちらの表記の人も迷わない
5. **手動マーカースタイル名「ルート」と自動ルート強調の用語衝突**(ux-designer の指摘)は design / ui-designer で見せ方を決める。スタイル名の変更が必要なら本 spec 内で扱う
