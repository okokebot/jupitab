# コード表の横型化と左利き表示・開放弦選択の修正 — 要求仕様

## 背景と目的

コード表ブロックは縦型ダイアグラム(上 = ナット、左 = 6弦)で、指板図ブロック(横型)と読む向きが 90° 違う。同じドキュメント内で 2 種類の空間変換を強いるのは、指板を内在化させたい学習者(ペルソナ)には余計な負荷になる。また、押弦済みの弦には開放/ミュート切替域が描画されないため、**押弦をいったん外さないと開放弦にできない**、開始フレットに関係なく開放弦を直接選べない、という操作上の欠陥がある。

ユーザー要望(2026-07-14):
1. 表示形式を指板図ブロックと同じ横型にする。右利き/左利きの指定も同様に持てること
2. 開始フレットにかかわらず、ゼロフレット = 開放弦を常に選択できること

## vision との対応

- **対応する柱**: 柱 1(コード表ブロック)の表示・操作改善。指板図(spec 002)と読み方を統一することで「同じ図法で指板を読む」訓練になる
- **非ゴール確認**: 抵触なし。spec 002 が非スコープにした「コード表の反転」の要望が実際に出たため、着手条件を満たした

## スコープ

- コード表ダイアグラムの**横型化**(指板図と同じ向き: 横軸 = フレット、縦軸 = 弦、1弦が上)。描画は `fretboardLayout.ts` のジオメトリを再利用する
- **右利き/左利き切替**(指板図 spec 002 と同一仕様: ブロック単位の「向き」セグメント、保存フィールド、反転時のヘッド側手がかり、aria-label)
- **開放弦の直接選択**: 開始フレットに関係なく、ナット外側の開放/ミュート域を全弦・常時クリック可能にする(押弦中の弦をクリックすれば開放に切り替わる)
- **○/× の意味と操作の提示**: 開放/ミュート域にホバープレビューと「次の状態を告げる」ツールチップを付け、記号の意味(○ = 開放、× = ミュート)を操作の場で学べるようにする(UI が先生の原則)
- **運指セレクト行への可視の弦番号ラベル**(6弦…1弦): 横型化で図(弦が縦並び)とセレクト(横一列)の空間対応が消えるため
- 既存機能の維持: コード名表示(SVG 内・画像出力に含まれる)、バレー、運指、ストローク再生、押弦マーカー再クリックでの解除

## 非スコープ

- **縦型表示の温存**(表示形式の選択肢化)— 横型に置き換える。着手条件: 共有画像(vision 柱 3)の受け手が横型を読めなかった事例が出たら再検討
- **運指セレクト行(SVG 外)の並び順変更** — データ順(6弦→1弦)のまま。横型化により図とセレクト行の空間対応はそもそも消えるため、並び替えでは解決せず、可視の弦番号ラベル(スコープ内)で補う
- **複数バレー・コード名からのフォーム自動生成** — 別要望(improvement-policy 柱 B-1)
- **TAB 譜の反転** — spec 002 と同じ理由で対象外

## ユーザーストーリー

- 学習者として、指板図とコード表を同じ向きで読みたい。図法の頭の切り替えをなくし、コードフォームをポジションとして覚えたいから
- 左利きギタリストとして、コード表も自分の楽器と同じ向きで見たい(spec 002 と同じ動機)
- 採譜中のユーザーとして、5 フレット始まりのフォームでも 6弦だけ開放、のような押さえ方を直接入力したい

## 受け入れ基準(EARS 形式)

- **AC-1**: WHEN コード表ブロックを表示 THEN 横型(横軸 = フレット、縦軸 = 弦、1弦が上)で描画され、コード名・バレー・運指数字・開放○/ミュート×が正しい位置に出る
- **AC-2**: WHEN 「向き」で「左利き」を選択 THEN 指板図と同じ鏡像描画(ナット/開始フレット側が右端)になり、文字は反転せず、「ヘッド側」の手がかりが表示され、状態が保存される
- **AC-3**: WHEN 開始フレットが 1 のとき THEN ナット(太線)が描画される。WHEN 開始フレットが 2 以上 THEN ナットは描画されず、フレット番号で位置が分かる
- **AC-4**: WHEN 押弦マーカーのある弦の開放/ミュート域をクリック THEN その弦が開放(○)になる(押弦を外す事前操作が不要)。開始フレットの値に関係なく機能する
- **AC-5**: WHEN 開放(○)の弦の開放/ミュート域をクリック THEN ミュート(×)になり、もう一度クリックすると開放に戻る
- **AC-6**: WHEN バレーを設定して反転表示 THEN バレーの帯が鏡像位置(正しいフレット)に、指定した弦範囲で描画される
- **AC-7**: WHEN 既存(縦型時代)のコード表ブロックを含むドキュメントを読み込む THEN データ変換なしでそのまま横型で表示される(frets/fingers/barres の意味は不変、migrate エラーなし)
- **AC-8**: WHEN 「▶ 鳴らす」をクリック THEN 反転表示でも従来どおりストローク再生される(表示だけの変更で再生データに影響しない)
- **AC-9**: WHEN 押弦マーカー(●)を再クリック THEN その弦はミュート(×)になる(現行挙動の維持。開放へは頭部クリック、解除は ● クリックの 2 経路を意図した設計とする)
- **AC-10**: WHEN 押弦中の弦の開放/ミュート域にホバー THEN 開放になることを示すプレビュー(薄い ○)と、次の状態・記号の意味を告げるツールチップが表示される

## 要確認

いずれも仮置きで実装を進める。問題があれば指摘してほしい:

1. **縦型は廃止**し横型に置き換える(表示形式の選択肢は設けない)。一般的なコード譜の縦型に慣れたユーザーには違和感の可能性があるが、アプリ内の図法統一(ペルソナの学習効率)を優先した
2. **`mirrored` はコード表ブロック自身の保存フィールド**(指板図と同一仕様)。既存の指板図ブロックから自動継承はしない — 「引き継ぐ」は「同じ指定方法を踏襲する」と解釈した
3. **開放/ミュート域のクリックサイクル**: 押弦中 → 開放、開放 ↔ ミュート。「なし(表示しない)」状態は現データモデルに存在しない(null = ミュート)ため設けない
