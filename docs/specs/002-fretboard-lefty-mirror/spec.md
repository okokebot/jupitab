# 指板図の左利き(左右反転)表示 — 要求仕様

## 背景と目的

指板図ブロックは右利きギター前提(ナットが左端、フレット番号が左→右に増加)で描画されている。左利きプレイヤーには自分の手元と鏡像になり、フレーズを読み取るたびに頭の中で反転する負荷がかかる。「フレット番号 → 音名 → 度数」の内在化(vision 柱 2)を目指すアプリで、その手前の「図を読む」段階に余計な変換を挟ませない。

## vision との対応

- **対応する柱**: 柱 1(指板図ブロック)の表示オプション。学習体験のアクセシビリティ改善
- **非ゴール確認**: 抵触なし。表示の切替のみで、DAW 化・浄書・共有プラットフォーム・モバイル編集のいずれにも近づかない。improvement-policy のロードマップ外だが規模が小さく、既存機能の読みやすさ改善なので割り込みを正当化できる

## スコープ

- 指板図ブロック単位の左右反転表示切替(ツールバーの「向き」セグメント: 右利き|左利き)
- 反転状態のドキュメントへの保存(エクスポート画像・共有時も見た目が再現されるように)
- 反転時の全描画要素の整合: フレット線、ナット、フレット番号、ポジションマーク、弦、クリック領域、マーカー、開放弦マーカー
- **図単体で向きが判別できる手がかり**(反転時に「ヘッド側」を図内に表示。ツールバーが付かないエクスポート画像でも向きが伝わるように)

## 非スコープ

- **コード表(ChordBlock)の反転** — 縦型ダイアグラムで反転の慣習が異なる(左利き用コード表は弦順を逆にする)。要望が出てから別 spec で
- **TAB 譜の反転** — TAB は時間軸表現であり左右反転の概念が適用されない
- **アプリ全体の「左利きモード」設定**(新規ブロックのデフォルトを反転にする)— まずブロック単位で価値を検証してから(検証項目は §ドッグフーディング参照)
- **弦の上下反転**(低音弦を上に表示)— 別の表示慣習の話であり混ぜない

## ユーザーストーリー

- 左利きギタリストとして、指板図を自分の楽器と同じ向き(ヘッドが右)で表示したい。鏡像の読み替えをせずにポジションを覚えたいから
- 右利きの著者として、左利きの友人に渡す図だけ反転して作りたい。ドキュメントごと・ブロックごとに向きを選べてほしいから
- 画像を受け取った左利きの友人として、その図がどちら向きかを図だけで判別したい。向きを誤解すると逆のポジションを覚えてしまうから

## 受け入れ基準(EARS 形式)

- **AC-1**: WHEN 指板図ツールバーの「向き」で「左利き」を選択 THEN ナットが右端に、フレット番号が右→左へ増加する鏡像で描画される(番号・マーカーラベルの文字自体は反転しない)
- **AC-2**: WHEN 反転表示中に任意のマス目をクリック THEN 見た目どおりの位置(その弦・そのフレット)にマーカーが追加され、選択・編集・削除も同じ位置で機能する
- **AC-3**: WHEN 反転 ON のドキュメントを保存して再読込、または JSON エクスポート → インポート THEN 反転状態が保持される
- **AC-4**: WHEN 反転フィールドを持たない既存ドキュメントを読み込む THEN 従来どおりの右利き表示になる(デフォルト OFF、migrate エラーなし)
- **AC-5**: WHEN 開放弦マーカー(fret 0)がある指板図を反転表示 THEN 開放弦マーカーはナットの右外側に表示される(エッジケース: `fretStart > 0` の図では開放弦領域自体が出ないこと)
- **AC-6**: WHEN 12 フレットを含む範囲を反転表示 THEN ポジションマーク(単点・12F の複点)も鏡像位置に描画される
- **AC-7**: WHEN 反転 ON の指板図を図単体で見る(ナットが描画されない `fretStart > 0` の図、エクスポート画像を含む) THEN ヘッド側を示す手がかりが図内に描画されており、向きが判別できる
- **AC-8**: WHEN 「向き」セグメントにポインタを合わせる THEN 作用の説明(左右反転すること、弦の並びは変わらないこと)が表示され、現在どちらの向きかが常にセグメント上で読める

## ドッグフーディング検証項目(実装後)

1. 初見でセグメントを押す前に結果を予想でき、押した結果(ハイポジション図含む)と一致したか
2. 数日後・PNG 単体でも図だけで向きを即答できたか
3. 左利き想定で指板図を 5 個作ったとき、毎回の切替を「全体設定が欲しい」と感じたか(アプリ全体デフォルトの要否判断の材料)

## 要確認

いずれも仮置きで実装を進める。問題があれば指摘してほしい:

1. **反転状態はブロック単位の保存フィールド**とした。理由: 画像出力(vision 柱 3)・共有時に作者の意図した向きが再現される必要があるため、閲覧環境の設定ではなくデータに持つのが正しいと判断
2. **`schemaVersion` は 1 のまま**(省略可能フィールドの追加のみのため)。CLAUDE.md の「保存形式を変えたらバージョンを上げる」の解釈を [ADR 0001](../../adr/0001-additive-optional-fields-keep-schema-version.md) で明確化した — 旧アプリ・既存 JSON バックアップとの互換を壊さないための判断
3. **並行 spec `001-fretboard-scale-marking`(draft)との実装順**: 本 spec の `fretboardLayout.ts` 抽出を先に実装する。scale-marking の自動マーカー描画が同じジオメトリを使えば反転にも自動対応できる
