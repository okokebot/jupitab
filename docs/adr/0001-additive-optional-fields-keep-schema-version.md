# 0001. 省略可能フィールドの追加では schemaVersion を上げない

- 日付: 2026-07-11
- ステータス: accepted

## 文脈

CLAUDE.md の不変条件は「保存形式を変えるときは `schemaVersion` を上げて移行関数を足す」としているが、「省略可能フィールドを 1 つ足すだけ」の変更(例: spec 002 の `FretboardBlock.mirrored?`)でも上げるべきかが曖昧だった。現行の `migrate.ts` はバージョン不一致を即エラーにするため、安易に上げると旧バージョンのアプリ・手元の JSON バックアップが新しいドキュメントを開けなくなる。

## 決定

`schemaVersion` を上げるのは**旧データの解釈が変わるとき**だけとする。具体的には: 必須フィールドの追加・削除・改名、既存フィールドの型や意味の変更、デフォルト値の解釈変更。**省略可能フィールドの追加で、欠落時の挙動が従来と完全に同じ場合はバージョンを上げない**(欠落 = 従来挙動、がフィールド定義のコメントで明示されていること)。

## 検討した代替案

- **フィールド追加のたびにバージョンを上げる** — 移行関数は空になるのに旧環境との互換だけが壊れる。ローカルファーストで JSON バックアップを推奨するアプリでは互換コストが利益を上回るため不採用
- **バージョンを完全に廃止し全フィールド省略可能で運用** — 解釈が変わる変更(弦番号規約の変更など)が起きたときに検出手段を失うため不採用

## 影響

- 省略可能フィールドの追加は `migrate.ts` の変更なしで通る(バージョン一致チェックのみ)
- 新フィールドを読むコードは必ず欠落(`undefined`)を従来挙動として扱うこと
- CLAUDE.md の不変条件の文言はこの ADR を正として解釈する(次回 CLAUDE.md 更新時に文言へ反映)
